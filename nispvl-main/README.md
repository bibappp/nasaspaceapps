# Агро-Севооборот

Веб-сервис поддержки решений для полей Северного Казахстана. Фермер заводит аккаунт, добавляет свои поля,
смотрит многолетние данные NASA по каждому полю (осадки, температура, NDVI, влажность почвы), оценивает риски
сезона и сравнивает 3–4 севооборота по **почве, воде, доходу и риску** за 3–5 лет — с экономикой, стресс-тестом
засухой и объяснением каждой оценки. Отчёты — PDF и Excel на русском, казахском и английском.

> **Это инструмент поддержки решений. Окончательное решение принимает фермер. Перед посевом посоветуйтесь с агрономом.**
> Вариант с лучшим взвешенным баллом помечается как рекомендуемый при выбранных весах; остальные остаются на экране,
> у каждого числа есть источник и статус проверки. Данных об урожайности конкретных полей у сервиса нет.

Интерфейс: русский, казахский, английский. **Казахский перевод требует вычитки носителем языка**
(`frontend/src/locales/kk.json`, `backend/app/locales/*.yaml`).

## Быстрый старт

### Docker (рекомендуется)

```bash
cp .env.example .env        # необязательно: без .env работает всё, кроме SMAP для новых полей
docker compose up --build
```

Сайт: http://localhost:8080 · API: http://localhost:8000/docs

Зависимости бэкенда ставятся по точным версиям из `backend/constraints.txt` (проверены на amd64 и arm64), поэтому pip
не перебирает версии и сборка воспроизводима. На медленной сети увеличьте тайм-аут загрузки пакетов:
`docker compose build --build-arg PIP_DEFAULT_TIMEOUT=300`. Диапазоны в `backend/pyproject.toml` проверены тестами
на нижних и на новейших версиях; после обновления зависимостей пересоберите образ без `-c`, прогоните тесты и
перезапишите `constraints.txt` (команда в его заголовке).

- **Демо без регистрации:** http://localhost:8080/demo — создаёт временную песочницу с двумя реальными полями
  (Шортанды, Акмолинская обл.; Костанайская обл.) и сохранёнными данными NASA из `data/demo/`. Работает без интернета.
  Песочница удаляется через `DEMO_TTL_DAYS` (3 дня).
- **Аккаунты и поля** хранятся в SQLite `data/app.db` (каталог `./data` смонтирован в контейнер) — переживают
  перезапуск и пересборку контейнеров. Проверено: `docker compose restart backend` — сессия и поля на месте.

### Локально

```bash
make install    # Python 3.11 venv в backend/.venv + npm install
make dev        # бэкенд :8000 и фронтенд :5173 (Vite проксирует /api на бэкенд)
```

|---|---|
| `make test` | тесты бэкенда (`pytest`): модель, правила, источники, API, аккаунты и изоляция, мониторинг, PDF, XLSX, переводы |

| `make offline-check` | демо «анализ → сравнение → слои → PDF» с полным запретом сети |
| `make demo` | заново скачать данные демо-полей в `data/demo/` (нужен интернет) |
| `make smap` | заранее скачать ряд SMAP для поля (нужен Earthdata) |
| `node scripts/e2e.cjs` | сквозная проверка в браузере (регистрация → поле → планировщик → PDF/XLSX → изоляция), нужен запущенный `make dev` и Playwright |

### Настройки (`.env`)

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `EARTHDATA_TOKEN` | — | токен NASA Earthdata для SMAP (Profile → Generate Token на https://urs.earthdata.nasa.gov) |
| `DB_PATH` | `DATA_DIR/app.db` | файл SQLite с пользователями, полями и анализами |
| `SESSION_DAYS` | 30 | срок жизни сессии |
| `COOKIE_SECURE` | 0 | `1` — cookie только по HTTPS (включить за TLS-прокси) |
| `ALLOW_REGISTRATION` | 1 | `0` — закрыть регистрацию |
| `DEMO_TTL_DAYS` | 3 | срок жизни демо-песочниц |
| `OFFLINE` | 0 | `1` — ни одного внешнего запроса |

Секретов в коде нет: только `.env` (в `.gitignore`). Без Earthdata всё работает, а весенний запас влаги новых полей
оценивается по NASA POWER — интерфейс об этом предупреждает.

### Безопасность учётных записей

Пароли — `scrypt` (n = 2¹⁴, r = 8, p = 1, соль 16 байт); сессия — случайный токен в cookie `HttpOnly; SameSite=Lax`,
в базе хранится только его SHA-256; изменяющие запросы требуют заголовок `X-Requested-With` (защита от CSRF);
10 неудачных входов подряд блокируют вход на 15 минут. Каждый запрос к полю или анализу фильтруется по владельцу:
чужое поле отвечает 404 (покрыто тестами `tests/test_accounts.py`).

### Отчёты

- **PDF** (A4, DejaVu Sans со всеми казахскими буквами): обложка, сводка, поле и данные (карта с пикселями MODIS),
  растительность, вода и засушливые годы, риски, сравнение вариантов, экономика, симуляция по годам, стресс-тест,
  рекомендованный вариант, допущения, ограничения, источники, место для подписей. В оценках сценариев — дни без покрова в год и индекс опасности эрозии с источником и статусом.
- **XLSX** (6 листов): Field Overview, Environmental Data (помесячно с 2000 г.), Crop Rotation Comparison (формулы
  взвешенного балла `SUMPRODUCT`, маржи и ±20 %, график), Historical Analysis (аномалии формулами, графики),
  Model Assumptions (все параметры правил), Sources and Methodology. Фильтры, закреплённые заголовки, форматы чисел, единицы.

### Демонстрация за 5 минут

1. `/demo` → дашборд → поле Шортанды (или Костанай).
2. «Мониторинг»: осадки, температура, NDVI и SMAP относительно нормы.
3. «История сезонов»: засушливые 2008, 2010, 2017, 2021–2023; кривая NDVI 2021 года.
4. «Планировщик»: четыре сценария по почве, воде, доходу и риску.
5. Ползунки весов — рейтинг пересчитывается сразу.
6. Засушливый год 2021 → «Рассчитать и сохранить» → «А если засуха?».
7. Блок «Рекомендуемый вариант»: почему, условия, данные, уверенность, ограничения.
8. «Отчёты»: PDF и Excel на нужном языке.

**Новое поле, первый запуск:** NASA POWER и SoilGrids приходят сразу (SoilGrids — до ~45 с, часто не отвечает),
NDVI MODIS и SMAP загружаются фоновыми задачами (~3 и ~6 минут на поле). Интерфейс показывает, что идёт загрузка,
и сам обновляет графики. Повторно — из кэша.

Все URL и параметры проверены живыми запросами 12–13.11.2026. Страница «Данные NASA» (`/nasa`) показывает то же самое в интерфейсе.

| Источник | Что берём | Разрешение | Охват | Доступ | Происхождение и главное ограничение |
|---|---|---|---|---|---|
| **NASA POWER** Daily API | осадки `PRECTOTCORR`, `T2M`, `T2M_MAX/MIN`, запасная влажность `GWETROOT` | ячейка ~0,5°×0,625° (≈55×43 км) | 1981 – наст. время, сутки, задержка несколько дней | без ключа | **реанализ** MERRA-2 / GEOS-IT, не измерение на поле: все поля в ячейке получают одно значение |
| **MODIS MOD13Q1 v6.1** через ORNL DAAC | NDVI + маска `pixel_reliability` (0–1) | пиксель ~232 м (≈5,4 га) | 18.02.2000 – наст. время, композит 16 дней | без ключа | спутник Terra; не больше 10 дат и окно ≤100 км на запрос, 30–50 с на запрос |
| **SMAP SPL3SMP_E v006** через OPeNDAP NASA | влажность верхних ~5 см в апреле–мае | сетка 9 км (≈6×13 км на 52° с. ш.), реально радиометр видит ~33–40 км | 31.03.2015 – наст. время, сутки | Earthdata | спутниковый радиометр; мёрзлая почва и снег отсекаются флагом качества; до 2015 г. данных нет |

| GPM IMERG Final v07 | — **не подключён** | 0,1° | по CMR 1998-01-01 … 2025-09-30, задержка ~3,5 мес. | Earthdata + одобрение приложения GES DISC | каталог CMR отвечает, но чтение данных возвращает 403, пока в профиле Earthdata не одобрено приложение «NASA GESDISC DATA ARCHIVE» (проверено 13.11.2026). Осадки берутся из POWER |
| Landsat C2 L2 (Planetary Computer) | — **не подключён** (заготовка) | 30 м | с 22.08.1982 | без ключа | NDVI берётся из MODIS 250 м |

Каждый источник — класс в `backend/app/data_sources/` с единым интерфейсом `fetch(field, start, end)`, файловым кэшем
(`data/cache/<источник>/<sha256>.json`), демо-данными и запасным вариантом. **GPM и Landsat подключаются без
переработки архитектуры:** реализовать `_fetch_live` в `gpm.py` / `landsat.py` (инструкции в docstring), вернуть
данные в том же формате, что POWER / MODIS, и поставить `enabled = True`.

### Расхождения с таблицей из задания

- **MODIS**: не больше 10 композитов на запрос (ответ 400 при 11) — берём 10 композитов вегетационного сезона (DOY 129–273) на каждый год.
- **SMAP**: суточный файл весит ~650 МБ, поэтому не `earthaccess`-скачивание, а вырезка окна 3×3 ячейки через OPeNDAP (~3 с на день). Ссылку на файл берём из каталога CMR: у свежих гранул идентификатор в каталоге не совпадает с именем файла.
- **SSL ORNL**: сертификат `modis.ornl.gov` выпущен в цепочке emSign — нужен `certifi ≥ 2026.10.23`.
- **GPM IMERG Final** по каталогу CMR заканчивается 30.09.2025 (статус COMPLETE).

## Модель

Простая, прозрачная, детерминированная, без машинного обучения (`backend/app/model/rotation.py`).

```
урожайность  = база культуры × индекс области × (1 + эффект предшественника)
               × (1 + штраф за монокультуру) × коэффициент влаги поля
коэф. влаги  = RY(W поля) / RY(W области),  RY(W) = 1 − Ky·(1 − min(1, W / потребность))   (FAO-33)
W            = осадки май–август + запас продуктивной влаги к посеву
запас влаги  = норма области × (SMAP апрель–май / медиана SMAP)  — без SMAP по осадкам сентября–апреля;
               не больше влагоёмкости метрового слоя (SoilGrids + Saxton & Rawls 2006); после пара больше
доход        = урожайность × цена − затраты
индекс почвы = 100 + Σ (баланс азота / 10 кг + баланс гумуса / 0,25 т) − штраф монокультуры
```

- **Оценки 1–5** (почва, вода, доход, риск) нормируются от худшего к лучшему значению среди сравниваемых вариантов **и** вариантов по умолчанию — поэтому монокультура не получает «5 за почву», даже если сравнить её только саму с собой.
- **Приоритет** задаёт веса оценок: пять готовых наборов в `model.yaml` или свои веса (ползунки в планировщике, `weights` в API; нормируются к сумме 1). Отдельные оценки от весов не зависят, поэтому интерфейс пересчитывает рейтинг мгновенно по той же формуле Σ wₖ·оценкаₖ.
- **Экономика**: выручка, затраты, валовая маржа, маржа при ценах −20 % / +20 %, безубыточный уровень цен — для каждого варианта.
- **Уверенность** варианта: доля использованных параметров с классом `literature` или `definition` (≥ 60 % — высокая, ≥ 30 % — средняя).
- **Засушливый год**: осадки май–август ниже 20-го перцентиля нормы 1991–2020 *или* аномалия ≤ −1σ. Доля — за последние 25 полных лет.
- **Стресс-тест**: любой год плана заменяется условиями засушливого года — 2021, если он засушливый и по данным поля, иначе самый сухой год ряда; в планировщике можно выбрать любой засушливый год из истории поля (`stress_year`).
- **Тренд NDVI**: максимум за сезон по годам, линейная регрессия; «растёт / снижается» только при p < 0,05.
- **Объяснения** собираются из шаблонов (`backend/app/locales/explain.yaml`) по сработавшим правилам, без LLM.

### Правила и их статус

Все числа — в `backend/app/rules/*.yaml`, у каждого `value`, `unit`, `source`, `status` и пояснение.
Загрузчик не запустит сервер, если у числа нет источника или статуса.

**Всего 149 значений: 23 проверено (`verified`), 126 — допущения (`assumption`)**, в интерфейсе помечены «требует проверки».
У каждого числа есть класс обоснованности `evidence` (обязательное поле, введено аудитом):

| Класс | Сколько | Что это |
|---|---|---|
| `literature` — подтверждено источником | 16 | число или диапазон найдены в тексте научного или официального источника |
| `agronomist_review` — проверить агрономом | 39 | косвенная опора: другой регион, аналог, один год, расчёт по балансу массы |
| `preliminary` — предварительное допущение | 79 | источника нет, или это параметр конструкции модели (шкалы, веса, пределы) |
| `definition` — определение или расчёт | 15 | определения из задания, тривиальные значения, опорные осадки, рассчитанные по NASA POWER |

Полный реестр с обоснованием каждого числа — [`docs/audit/PARAMETERS.md`](docs/audit/PARAMETERS.md),
отчёт об аудите — [`docs/MODEL_AUDIT.md`](docs/MODEL_AUDIT.md), ограничения и как их устранить —
[`docs/LIMITATIONS.md`](docs/LIMITATIONS.md). Воспроизвести аудит: `make audit`.

### Главные ограничения модели

- Урожайность и затраты альтернативных культур — допущения; в консервативном сценарии монокультура выигрывает по доходу.
- Эффекты предшественников взяты из опытов в Канаде и зависят от азотного питания; удобрения не моделируются.
- Горизонт 3–5 лет обрезает пользу пара и бобовых в последнем году плана.
- Цены и затраты постоянны на весь план; влага поля оценивается по данным с ячейками 9–50 км.
- SoilGrids в верхних сантиметрах степных почв может завышать органический углерод; при гумусе > 8 % в слое 0–30 см интерфейс предупреждает.

Подробно, с влиянием на результат и рекомендациями, — `docs/LIMITATIONS.md`.

### Что показал расчёт демо Шортанды (фактические цифры; правила после аудита)

| Показатель | Результат |
|---|---|
| Засушливые годы 2002–2026 | 2008, 2010, 2017, 2021, 2022, 2023 — **6 из 25, «каждый 4-й год»** |
| Тренд NDVI 2000–2026 | **стабилен** (наклон −0,0002/год, p = 0,96) |
| Сезон 2026 | осадки 148 мм (94 % среднего), температура +2,8 °C к средней, 45 дней с Tmax > 30 °C — высокий уровень по жаре |
| Маржа за 4 года, тг/га (цены МСХ РК 27.07.2026) | пшеница по пшенице **96 992**; пшеница→чечевица→пшеница→лён **158 155**; пшеница→горох→рапс→пар **105 569**; пшеница→нут→подсолнечник→пшеница **158 891** |
| Приоритет «доход» | вариант с чечевицей и льном (балл 4,55), затем с нутом и подсолнечником (4,23); уверенность — низкая (23 % параметров подтверждены) |

«Каждый третий год засушливый» из питча **не подтвердилось** (каждый 4-й). «+25 % дохода за 4 года» **не воспроизводится
как устойчивый результат**: знак выигрыша зависит от урожайности и затрат альтернативных культур, а они пока допущения

| Метод | Что делает |
|---|---|

Новое поле запускает фоновые загрузки MODIS (сезон и межсезонье) и SMAP; пока данных нет, месяц — `missing` с `missing_reason`. Пороги — `rules/erosion.yaml`, контракт — `docs/contracts/` |

## Ретро-проверка

Полей с подтверждённой историей «пшеница после бобовых» пока **нет**, и страница так и пишет — никаких выдуманных
примеров. Заявки из формы сохраняются в `data/retro/submissions/` со статусом `unverified` и на сайте не показываются.
Проверенное поле публикуется, когда его JSON кладут в `data/retro/verified/` (формат: `id`, `name`, `region`,
`geometry`, `history`, `evidence`).

  урожайность пшеницы; засуха сильнее бьёт по культурам с высоким Ky; свои веса меняют рейтинг), правила (у каждого

  PDF (три языка, казахские буквы, встроен только DejaVu, числа совпадают с моделью), XLSX (листы, формулы, фильтры,

  вёрстка 390 px без горизонтальной прокрутки.
